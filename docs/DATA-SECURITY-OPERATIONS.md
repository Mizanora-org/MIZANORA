## Security review — changes aur bachi hui risk

- **Admin authorization:** Admin SDK Firebase ID-token verification + configured `ADMIN_UID` (preferred) ya verified `NEXT_PUBLIC_ADMIN_EMAIL`. Firestore quota par access ke liye `orders`/`productCosts` reads par depend nahin. SDK unavailable ho to Identity Toolkit verification; legacy Firestore rules-probe sirf explicit `ADMIN_RULES_FALLBACK=1` par. Missing config fail-closed. `ADMIN_UID` production mein set karna deployment se **pehle** zaroori hai.
- **SSRF / media abuse:** TV, images aur imported images pinned-DNS `undici` connector, IP range filtering, har redirect check, time/byte bounds. TV streams signed ya saved channel se; image relay public hosts tak allowed hai unless `NEXT_IMAGE_PROXY_HOSTS` set ho. Apne real image hosts ki allowlist lagana behtar hai. Per-instance limits fleet-wide WAF ka substitute nahin.
- **Assistant discounts:** Purani public-default key se forge hone wale Rs-off tokens reject; signed token ab product + us waqt ki authoritative price se bound hai. `DEAL_SECRET` ek long private value rakhein, warna Firebase server credentials se stable key banti hai. Dono absent hon to local per-instance key cross-worker discounts ko invalidate karegi. Public assistant POST 16 KiB tak capped + per-instance 20 req/min IP rate limit; paid AI ke liye Vercel WAF bhi chahiye.
- **Ads API:** impression/click tokens ab public constant se sign nahin hote: server-only `AD_SECRET` (ya Admin credentials) + constant-time verify, matching key/campaign, revoked/expired key aur replay/per-IP limits. Shop `self` ads sirf configured site/deployment origins se serve hote hain; arbitrary Host header trusted nahin. Client ka bheja hua click href API response se remove hua. Ye per-instance protection hai; high-volume distributed fraud ke liye WAF/monitoring ab bhi zaroori hai.
- **IP blocking:** `/admin/security` se 1h/24h/7d/30d block, un-block, recent alerts. Node middleware dynamic requests/APIs par private blocklist lagata hai; admin security recovery route verified owner ke liye khuli hai. RTDB unreachable ho to cached blocks tak enforcement mumkin hai, **global guaranteed ban nahin**. Vercel/controlled proxy IP headers hi trust hote hain; CDN/WAF par global limits aur network block enable karein.
- **Public RTDB writes:** `database.rules.json` mein `presence`/`stats` read/write false, tracker ab `/api/telemetry` ko call karta hai. Rules Firebase Console mein **publish** karni hongi; Git mein file hona live security change nahin. Pehle new app deploy, phir turant rules publish. `siteStatus` public read hi rehta hai; Admin SDK server writes bypass rules.
- **Firestore rules:** `users/{uid}` write fields/list sizes aur new `reviews` field/type limits tighten ki hain. Existing profile mein legacy extra fields preserve hote hain; update sirf allowed keys. Rules publish karne se pehle test Firebase project par signup, saved addresses, wishlist aur review flow verify karein.
- **Orders during Firestore quota:** breaker active ho to **Firestore retry nahin**. Eligible order private RTDB `ordersBackup` mein save hota hai; **coupon code** ko validate nahin kar sakte, is liye coupon ke saath order 503 reject hota hai. COD seedha backup hai; prepaid reference save hota hai magar admin ko payment manually verify karni hai. Worker referral save hota hai magar quota-period commission automatically create nahin hoti — admin ko move karne ke baad manually reconcile karna hoga. RTDB fail ho to 503 aur saaf 'NOT placed' message, fabricated confirmation nahin. Customer ID + matching phone se backup order track ho sakta hai. Admin Dashboard se order baad mein Firestore mein move karein; dismiss confirmation mangta hai. Archive products par stale live price override ka risk hai: production catalogue compare karein; quota fallback ko payment-grade price guarantee na samjhein.
- **Retention:** `vercel.json` daily `/api/cron/security` trigger add hua; production mein random `CRON_SECRET` set karein. Logger active hone par once/day fallback cleanup bhi karta hai. Cron/env deploy na hone par idle site ki purani entries automatically expire nahin hongi.
- **HTML/cache:** local baseline home HTML **2,033,503 bytes**, naya offline build **1,272,756 bytes** (~37.4% kam; gzip ~109 KB); home par bounded category shelves/feed/product cards; TV 100k list banner ke client props mein nahin jati. `/api/stats` 5-minute public CDN cache aur visible-tab refresh, admin dashboard live 60s / full 5min. Real PageSpeed/Lighthouse **nahin** chal saka (Chrome unavailable); production field metrics measure karni hain.

## Safe production rollout (manual; current branch ne nahin kiya)

1. `ADMIN_UID`, Firebase Admin credentials aur RTDB URL verify karein; `CRON_SECRET`, (recommended) `AD_SECRET` + `DEAL_SECRET`, aur (optional) `TELEMETRY_SECRET` set karein. `NEXT_IMAGE_PROXY_HOSTS` ko actual CDN hosts tak restrict karein. GitHub token **server-only**, sirf is repo ka Contents: Read/Write; `GITHUB_BRANCH` wahi ho jo Vercel production build deploy karti hai. Private keys aur token `NEXT_PUBLIC_` mein kabhi nahin.
2. New app deploy karein; login, `/admin/connections`, `/admin/security`, `/api/stats`, signup/reviews, COD test order aur order tracking smoke-test karein. Phir Firebase Console mein `database.rules.json` aur `firestore.rules` publish karein. Check karein browser RTDB direct writes denied aur site tracking ab bhi server endpoint se chal rahi hai. Existing data ka offline backup rakhein.
3. Admin → Data mein **ek type** ki public setting ko inspect karke PUBLIC confirmation se capture karein. Signed URLs, Xtream credentials, personalized links ya private movies ko capture **mat** karein. GitHub commit ke baad Vercel deployment complete hone ka wait karein; tab Verify se deployed ↔ repo match aur optional old Firestore comparison check karein. Dusri setting par bhi yehi process; incomplete shards/oversize/corrupt parts par ruk jaayein.
4. Public snapshot activation ke baad sirf archive editor se update karein. Repo commit deploy se aage ho to editor 409 deta hai; latest deployment ka wait karein. **Firestore settings/orders/customer data manually delete na karein**. Product duplicates sirf Admin → Archive ke exact deployed part + matching `updatedAt` verification ke baad clear karein. Rollback par old Firestore fallback preserved hai; rollback se pehle confirm karein old copy stale na ho.
5. Vercel security/WAF rate limits, availability alerts aur quota monitoring configure karein; RTDB outage ya suspicious IP ka end-to-end production test safely karein. Daily cron ka authorized status check karein; `CRON_SECRET` ko URL mein nahin, Authorization header mein bheja jata hai.
